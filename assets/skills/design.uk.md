# Навичка: дизайн HTML-артефакту

Артефакт — це **один самодостатній HTML-документ** у блоці ` ```html `. Він
відкривається в пісочниці на телефоні, тому зовнішні ресурси, сховище й міст
застосунку недоступні.

## 1. Коли робити артефакт
- Інтерактивна сторінка: калькулятор, гра, демо, візуалізація, дашборд.
- Не роби HTML для звичайного тексту, списку чи таблиці — для цього є Markdown.

## 2. Обов'язкова основа
```html
<!doctype html>
<html lang="uk">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
<title>Коротка назва</title>
<style>/* весь CSS тут */</style>
</head>
<body>
<!-- розмітка -->
<script>/* весь JS тут */</script>
</body>
</html>
```
- Усе CSS і JS — всередині. Жодних `<link>`, CDN, Google Fonts, зовнішніх
  картинок і `fetch`/`XMLHttpRequest`.
- Картинки — inline SVG або CSS-градієнти.
- `lang` — мова інтерфейсу артефакту.

## 3. Пісочниця: що не працює
- `localStorage`, `sessionStorage`, cookie, IndexedDB — кидають помилку.
  Тримай стан у змінних; якщо треба зберегти — обгорни в `try/catch`.
- Доступ до файлів, буфера обміну й батьківської сторінки заборонено.
- `alert`, `confirm`, `prompt` технічно можливі, але виглядають грубо —
  роби власні inline-повідомлення.
- Зовнішні посилання `http(s)` відкриває браузер; внутрішні `#anchor` — ні.

## 4. Телефон-first
- Цільова ширина — 360–400 CSS px. Верстка не повинна мати горизонтального
  скролу: `*{box-sizing:border-box}`, `img,svg,video{max-width:100%}`,
  `overflow-wrap:anywhere` для довгих слів.
- Великі таблиці не вміщуються — заміни картками «ключ — значення» або
  дозволь скрол лише всередині контейнера таблиці.
- Основні дії — внизу, великі (мінімум 44×44 px), з відступом 8–12 px.
- Врахуй `env(safe-area-inset-bottom)` для нижньої панелі.
- Desktop — через `@media (min-width:600px)`, а не навпаки.

## 5. Візуальна мова FunaChat
Темна, спокійна, без «неонового» перевантаження.
```
--bg:#0F1216; --surf:#151A20; --on:#E3E7EC; --var:#9BA6B3;
--dim:#6F7A87; --outline:#313A45; --primary:#A8C7FA;
--on-primary:#0B2D5E; --err:#FFB4AB; --ok:#8FD9A8;
```
- Фон `--bg`, картки `--surf`, рамки `--outline`, акцент `--primary`.
- Шрифт: `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`.
  База 16 px, `line-height:1.5`, максимум ~65 символів у рядку.
- Заголовки — 1.25–1.75 rem, не більше двох рівнів.
- Радіуси 12–16 px, тіні майже непомітні, без різких градієнтів.
- Контраст тексту до фону — не менше 4.5:1.

## 6. Доступність і поведінка
- Семантика: `<button>`, `<label>`, `<main>`, `<nav>`; не роби кнопки з `<div>`.
- Видимий `:focus-visible`, підтримка клавіатури, `aria-live` для результатів.
- Анімації 150–250 мс; поважай `prefers-reduced-motion: reduce`.
- Стан завжди видимий: завантаження, порожній список, помилка, успіх.
- Ніяких вигаданих даних: якщо це демо — підпиши «демо-дані».

## 7. Продуктивність
- Орієнтовно до 100 КБ коду; без важких бібліотек.
- Не створюй тисячі DOM-вузлів; для графіків — `<canvas>` або SVG.
- Анімацію — через `requestAnimationFrame`, а не `setInterval(…, 1)`.
- Ніяких нескінченних циклів і синхронних обчислень на 10 секунд.

## 8. Чек-ліст
- [ ] Один файл, увесь CSS/JS всередині, без зовнішніх запитів.
- [ ] Немає горизонтального скролу на 360 px.
- [ ] Кнопки ≥44 px, контраст ≥4.5:1, є focus-стан.
- [ ] Немає `localStorage` без `try/catch` і зовнішніх картинок.
- [ ] Є `<title>` — він стане назвою файлу.
- [ ] На телефоні все читається без зуму.
