# Навык: DOCX (Word)

Цель — аккуратный **редактируемый** документ, а не текстовый файл с разметкой.
DOCX создаётся инструментом `doc` (`"format":"docx"`).

## 1. Перед созданием
1. Определи цель, аудиторию и объём. Если пользователь не уточнил — прими
   разумное допущение и озвучь его одной строкой.
2. Составь план: 3–7 разделов, в каждом 2–5 абзацев.
3. Собери факты. Не выдумывай цифры, даты, цитаты, источники и ссылки.
4. Сначала напиши полный текст, затем один раз вызови `doc` — не собирай файл
   по частям.

## 2. Разметка, которую понимает генератор
- `# Заголовок` — подзаголовок раздела (жирный, крупнее). Ровно один `#`.
- `- пункт` или `* пункт` — маркированный список с `•`.
- Пустая строка — интервал между абзацами.
- Нумерацию пиши текстом: `1. …`, `2. …`.

**Не поддерживается:** таблицы, изображения, настоящие стили Heading, жирный и
курсив внутри абзаца, HTML, вложенные списки. Не пиши `**`, `*`, `` ` ``,
`<b>`, `|таблица|` — генератор их вырежет, а структура пропадёт. Вместо
таблицы — список «Параметр — значение» или «Шаг 1 — результат».

## 3. Структура хорошего документа
1. Вступление: зачем документ и для кого (2–3 предложения).
2. Основная часть: разделы от общего к конкретному.
3. Практика: шаги, примеры, команды.
4. Вывод или следующие шаги.
Название берётся из `title` — не дублируй его первой строкой.

## 4. Объём и стиль
- 3–10 страниц — норма. Жёсткий потолок — 1.5 млн символов, но такой документ
  никто не читает.
- Один абзац = одна мысль, 3–6 предложений.
- Активный залог, конкретные глаголы, без воды и канцелярита.
- Термины одинаковые по всему тексту; расшифруй аббревиатуру при первом
  упоминании.

## 5. Вызов
```json
{"tool":"doc","format":"docx","title":"Название документа","text":"# Раздел\n\nТекст…","path":"docs/name.docx"}
```
`path` можно не указывать — файл попадёт в `docs/<title>.docx`. Расширение
всегда согласуется с форматом автоматически.

## 6. После создания
- Одной–тремя строками скажи, что внутри.
- Добавь карточку файла:
```attach
/sdcard/Download/FunaFiles/docs/name.docx
```

## Чек-лист
- [ ] Есть вступление и вывод/следующие шаги.
- [ ] Нет Markdown-символов, которые станут мусором.
- [ ] Нет выдуманных фактов, источников и ссылок.
- [ ] Названия разделов конкретные, не «Общее».
- [ ] Файл создан один раз, а не пять раз с разными именами.
