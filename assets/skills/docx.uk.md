# Навичка: DOCX (Word)

Мета — охайний **редагований** документ, а не текстовий файл із розміткою.
DOCX створюється інструментом `doc` (`"format":"docx"`).

## 1. Перед створенням
1. Визнач мету, аудиторію й обсяг. Якщо користувач не уточнив — прийми розумне
   припущення й озвуч його одним рядком у відповіді.
2. Склади план: 3–7 розділів, у кожному 2–5 абзаців.
3. Збери факти. Не вигадуй цифри, дати, цитати, джерела та посилання.
4. Пиши спочатку повний текст у відповіді-чернетці (подумки), потім один раз
   виклич `doc` — не створюй документ частинами.

## 2. Розмітка, яку розуміє генератор
- `# Заголовок` — підзаголовок розділу (жирний, більший). Рівно один `#`.
- `- пункт` або `* пункт` — маркований список із `•`.
- Порожній рядок — інтервал між абзацами.
- Нумерацію роби текстом: `1. …`, `2. …`.

**Не підтримується:** таблиці, зображення, справжні стилі Heading, жирний і
курсив усередині абзацу, HTML, вкладені списки. Не пиши `**`, `*`, `` ` ``,
`<b>`, `|таблиця|` — генератор їх просто виріже, а структура зникне.
Замість таблиці — список «Параметр — значення» або «Крок 1 — результат».

## 3. Структура хорошого документа
1. Вступ: навіщо документ і для кого (2–3 речення).
2. Основна частина: розділи від загального до конкретного.
3. Практика: кроки, приклади, команди.
4. Висновок або наступні кроки.
Назва документа генерується з `title` — не дублюй її першим рядком.

## 4. Обсяг і стиль
- 3–10 сторінок — норма. Технічна стеля — 1.5 млн символів, але такий
  документ ніхто не читає.
- Один абзац = одна думка, 3–6 речень.
- Активний стан, конкретні дієслова, без води й канцеляриту.
- Терміни однакові по всьому тексту; розшифруй абревіатуру при першій появі.

## 5. Виклик
```json
{"tool":"doc","format":"docx","title":"Назва документа","text":"# Розділ\n\nТекст…","path":"docs/nazva.docx"}
```
`path` можна не вказувати — файл ляже в `docs/<title>.docx`. Розширення
завжди узгоджується з форматом автоматично.

## 6. Після створення
- Одним–трьома рядками скажи, що всередині.
- Додай картку файлу:
```attach
/sdcard/Download/FunaFiles/docs/nazva.docx
```

## Чек-ліст
- [ ] Є вступ і висновок/наступні кроки.
- [ ] Немає Markdown-символів, які стануть сміттям.
- [ ] Немає вигаданих фактів, джерел і посилань.
- [ ] Назви розділів конкретні, не «Загальне».
- [ ] Файл створено один раз, а не п'ять разів із різними назвами.
