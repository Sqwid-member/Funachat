# Навичка: документація

Мета — текст, за яким людина **зможе повторити дію**, а не перелік очевидностей.
Документація пишеться для конкретного читача й конкретної версії продукту.

## 1. Перед написанням
1. Визнач читача: новачок, досвідчений користувач, розробник.
2. Визнач мету: встановити, налаштувати, інтегрувати, полагодити.
3. Збери факти з наявних файлів, коду, конфігурації. Не вигадуй команди,
   шляхи, прапорці, версії, обмеження й поведінку.
4. Якщо чогось не знаєш — або перевір, або чесно познач «не перевірено».

## 2. Структура
1. Що це і навіщо (2–4 речення).
2. Вимоги: ОС, версії, права доступу.
3. Встановлення або підключення — покроково.
4. Швидкий старт: мінімальний робочий приклад.
5. Основні сценарії використання.
6. Довідка: параметри, команди, поля, формати.
7. Обмеження й безпека.
8. Проблеми та їх вирішення.
9. Changelog або «що далі».

Кожен крок починай з дієслова: «Натисни», «Встав», «Запусти».
Один крок = одна дія. Не змішуй перевірку й налаштування в одному пункті.

## 3. Формат
- Markdown: `.md` через `write`; DOCX/PDF — через `doc`.
- Заголовки `#`/`##`/`###`, без пропусків рівнів.
- Код — у ``` з мовою: ```bash, ```json, ```http.
- Шляхи й імена — моноширинні: `/sdcard/Download/FunaFiles`.
- Попередження — окремим блоком **Увага:** або **Безпека:**, не в кінці абзацу.
- Таблиці в Markdown допустимі; у DOCX/PDF — ні (див. навички docx/pdf).
- Посилання — на реальні файли й розділи, не на вигадані URL.
- Мова одна на весь документ; терміни однакові.

## 4. Приклад README
```markdown
# Назва

Одне речення: що робить продукт.

## Вимоги
- Android 8.0+
- 50 МБ вільного місця

## Швидкий старт
1. Встанови APK.
2. Відкрий застосунок і увійди.
3. Напиши перше повідомлення.

## Налаштування
- **Адреса** — за замовчуванням `http://127.0.0.1:8787`.
- **Ключ** — видається в Налаштуваннях.

## Проблеми
### Сервер не відповідає
Перевір, що застосунок відкритий і порт не зайнятий.
```

## 5. Точність
- Команди копіюються як є: без «приблизно» й без зайвих пробілів.
- Якщо показано вивід — познач, що це приклад, і не вигадуй повний лог.
- Секрети (токени, паролі, ключі) — лише як `fk-…`, `sk-…`, без реальних значень.
- Числа й ліміти беруться з коду або конфігурації, а не з пам'яті.
- Версії — з `build.sh`/manifest, не з припущень.

## 6. Перевірка перед віддачею
- Пройди документ очима новачка: чи вистачить кроків, щоб дійти до результату?
- Кожна команда має місце, де її виконувати (телефон, термінал, ПК).
- Кожне посилання веде на існуючий файл або розділ.
- Немає суперечностей між розділами.
- Немає вигаданих функцій «на майбутнє» без позначки «план».

## 7. Чек-ліст

- [ ] Кроки послідовні, з дієсловами на початку.
- [ ] Команди, шляхи й ліміти відповідають реальному продукту.
- [ ] Немає секретів і вигаданих джерел.
- [ ] Є розділ проблем і наступних кроків.
