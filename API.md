# FunaChat Local API

OpenAI-сумісний сервер усередині FunaChat. Працює, поки живий процес застосунку.
Ключ і порт — у застосунку: **Налаштування → Local API**.

- База: `http://127.0.0.1:8787/v1` (у LAN-режимі — `http://<ip-телефона>:8787/v1`)
- Авторизація: `Authorization: Bearer fk-…` (або `x-api-key: fk-…`)
- Ключ перевіряється на **кожному** запиті, включно з `/health` і `/v1/models`.
- CORS: preflight `OPTIONS` без ключа, відповіді з `Access-Control-Allow-Origin: *`

## Ендпоінти

| Метод | Шлях | Опис |
|---|---|---|
| GET | `/health` | стан, версія, список моделей, `tools: true` (потрібен ключ) |
| GET | `/v1/models` | список моделей |
| GET | `/v1/models/{id}` | одна модель (404, якщо немає) |
| POST | `/v1/chat/completions` | чат, `stream`, `tools`, `tool_choice` |
| POST | `/v1/completions` | legacy `prompt` → `text` |

## Моделі

| id | model_type | thinking | search |
|---|---|---|---|
| `deepseek-chat` | default | ні | ні |
| `deepseek-reasoner` | expert | так | ні |
| `deepseek-expert` | expert | так | ні |
| `deepseek-search` | default | ні | так |

Невідомий `model` мапиться на модель із налаштувань застосунку, тож клієнти
з зашитим `gpt-4o` теж працюють.

Додаткові необовʼязкові поля запиту: `"thinking": true`, `"search": true`.

## Приклади

```bash
KEY=fk-...
curl -s -H "Authorization: Bearer $KEY" http://127.0.0.1:8787/v1/models

curl -s -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"привіт"}]}' \
  http://127.0.0.1:8787/v1/chat/completions

curl -N -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"stream":true,"messages":[{"role":"user","content":"привіт"}]}' \
  http://127.0.0.1:8787/v1/chat/completions
```

## Tools (function calling)

Передаються як у OpenAI. Сервер вставляє оголошення інструментів у промт,
а блоки моделі перетворює на `tool_calls`.

```bash
curl -s -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" -d '{
  "model": "deepseek-chat",
  "messages": [{"role":"user","content":"Яка погода в Києві?"}],
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "Погода за містом",
      "parameters": {"type":"object","properties":{"city":{"type":"string"}},"required":["city"]}
    }
  }],
  "tool_choice": "auto"
}' http://127.0.0.1:8787/v1/chat/completions
```

Відповідь:

```json
{"choices":[{"index":0,"finish_reason":"tool_calls","message":{
  "role":"assistant","content":"",
  "tool_calls":[{"id":"call_…","type":"function",
    "function":{"name":"get_weather","arguments":"{\"city\":\"Київ\"}"}}]}}]}
```

Далі клієнт додає в `messages` повідомлення `role:"tool"` з `tool_call_id`
і результатом — і повторює запит. Історія з `tool_calls`/`tool` коректно
склеюється в промт.

`tool_choice`: `auto` (типово), `none`, `required`/`any`,
`{"type":"function","function":{"name":"…"}}` (примусовий виклик).

Стрім із `tools`: текст не стрімиться (щоб не показати службовий блок),
наприкінці приходить один кадр з `tool_calls` і `finish_reason:"tool_calls"`.

## Поведінка

- Кожен запит — нова сесія DeepSeek, після відповіді видаляється
  (вимикається перемикачем «Видаляти сесію після запиту»).
- Запити серіалізуються: PoW важкий для телефона.
- Ліміт тіла запиту — 8 МБ.
- `usage` оцінюється приблизно (символи/3), бо апстрім його не віддає;
- відповідь апстріму без стріму читається до 32 МБ; один SSE-кадр — до 8 МБ.
- Помилки DeepSeek: у стрімі — кадр `{"error": "…"}` + `[DONE]`,
  у non-stream — HTTP 502, якщо тексту ще не було.
- Токен DeepSeek прострочений (апстрім 401) — HTTP 401
  `{"error":{"type":"authentication_error"}}` в обох ендпоінтах:
  клієнту треба оновити сесію в застосунку, а не повторювати запит.
- Копія відповіді для non-stream JSON — до 2 000 000 символів; у стрімі
  текст іде без цієї стелі (обмежує лише сама модель).
- У `/v1/completions` промт також обрізається до 1 000 000 символів.

## Захист і ліміти

**Захист акаунта** (Налаштування → Захист акаунта, типово увімкнено):

- пауза між запитами completion — 3 с + джитер до 0.4 с;
- не більше 12 запитів на хвилину та 400 на добу;
- після 401 — пауза 30 хв, після 403 — 30 хв, після 429 — 5 хв
  (подвоюється до 30 хв), після тексту зі словами risk/blocked/abnormal — 60 хв;
- 5xx і мережеві помилки паузу **не** ставлять;
- паузу можна зняти кнопкою «Зняти паузу»;
- лічильники зберігаються між перезапусками, скидаються на нову добу (UTC).

Ліміти діють і на чат у застосунку, і на локальний API — це один акаунт.

**Локальний API:**

- `Authorization: Bearer fk-…` або `x-api-key: fk-…` (порівняння стале за часом);
- 120 запитів/хв з однієї IP → далі `429 rate_limit_error`;
- максимум 8 одночасних з'єднань → далі `503`;
- тіло запиту до 8 МБ, таймаут читання 30 с;
- до 100 заголовків запиту → далі `431`;
- лічильники IP тримаються до 2 хвилин, мапа обмежена 512 записами;
- промт обрізається до 1 000 000 символів (початок + кінець, середина
  позначається «частину історії опущено»);
- результат одного інструмента в авто-режимі — до 12 000 символів;
- у запиті враховуються щонайбільше 64 інструменти; опис кожного — до 500
  символів, схема аргументів — до 8 000; службова преамбула з описами
  інструментів — до 60 000 символів (разом із промтом усе одно ≤1 000 000);
- типово bind `127.0.0.1`; LAN вмикати лише за потреби;
- блокування FunaChat діє й на API: поки застосунок заблокований і не
  розблокований паролем, усі `/v1/*` відповідають `503 server_error`
  (ключ міг осісти в чужому конфігу, а пароль знає лише власник);
  виняток — `GET /health`: він лишається `200`, але віддає `"locked": true`
  і `"ok": false`, щоб клієнт бачив причину;
- `GET /health` віддає `version`, `model`, `tools`, `auto_tools`, `subagents`,
  `stream`, `locked` і повний список `endpoints`;
- застосунок не має резервних копій (`allowBackup=false`);
- cleartext дозволено лише тому, що локальний API та reverse-proxy слухають
  `http://127.0.0.1` — назовні застосунок ходить тільки через HTTPS;
- `session.json` у `Download/FunaFiles` видаляється після успішного імпорту.

**Відбиток клієнта** береться з `session.json`: `x-client-version`,
`x-device-model`, `x-client-locale`, `x-client-timezone-offset` — запити
виглядають як з того самого застосунку, що й експортував токен.

## Поради проти блокування

1. Не ділити токен між пристроями та не запускати API у публічній мережі.
2. Не ставити ліміти «в нуль» і не ганяти сотні запитів на годину — це
   головна ознака автоматизації.
3. Тримати `x-client-version` рівним версії застосунку, з якого експортовано токен
   (імпорт робить це автоматично).
4. Після 401/403 — перевірити акаунт у застосунку DeepSeek, не повторювати запити.

## Інструменти (tools)

`GET /v1/tools` — список інструментів, які сервер виконує **сам** без вашої участі.
Формат OpenAI (`{"object":"list","data":[{"type":"function","function":{…}}]}`).

Вбудовані інструменти:

| name | аргументи | що робить |
|---|---|---|
| `time` | `tz?`, `offset_days?`, `offset?` | поточні дата/час, ISO, зона, epoch |
| `calc` | `expr`, `deg?` | `+ - * / % ^`, дужки, `sin/cos/tan`, `log/ln/exp`, `sqrt`, `pi`, `e` |
| `convert` | `value`, `from`, `to` | довжина, маса, дані, швидкість, об'єм, температура (°C/°F/K) |
| `random` | `kind`, `min?`, `max?`, `items?`, `count?` | `int`, `float`, `uuid`, `bytes`, `choice` |
| `base64` | `op`, `text` | `encode` / `decode` |
| `hash` | `algo`, `text` | `md5`, `sha1`, `sha256`, `sha512` |
| `skill` | `name` | вбудована інструкція: `docx`, `pdf`, `design`, `docs` (мова — `lang`, за замовчуванням мова інтерфейсу) |
| `subagent` | `task` або `tasks[]`, `system?` | 1–4 окремі сесії автономно виконують підзадачі й повертають лише результат |

### Навички (`skill`)

`skill` віддає текст інструкції, який модель має прочитати **перед**
створенням артефакта:

| name | для чого |
|---|---|
| `docx` | Word: структура, підтримувана розмітка, обсяг, чек-ліст |
| `pdf` | PDF: A4, поля, ліміт 250 сторінок, що генератор не вміє |
| `design` | HTML-артефакт: пісочниця, телефон-first, палітра FunaChat, a11y |
| `docs` | документація: структура, точність команд, README, troubleshooting |

Аліаси: `word`/`doc` → `docx`, `html`/`ui`/`artifact` → `design`,
`documentation`/`report` → `docs`. Файли лежать в
`assets/skills/<name>.<lang>.md`; якщо мови немає — `en`, потім `uk`.
У чаті агент сам викликає `skill` перед `doc`; у режимі `auto_tools`
модель робить це за системною інструкцією.

### Авто-виконання

Два рівноцінні способи:

```json
{"model":"deepseek-chat","messages":[…],"auto_tools":true}
```

```json
{"model":"deepseek-chat","messages":[…],"tools":"auto"}
```

Сервер сам викликає модель, виконує інструменти (до 4 раундів, до 8 викликів
за раунд) і повертає готову відповідь — клієнт не бачить службових блоків.
`auto_tools` можна поєднувати зі своїми `tools[]` — вони додаються до
вбудованих без дублікатів. Промт між раундами теж тримається в межах
1 000 000 символів.

Без `auto_tools` / `tools:"auto"` поводження звичайне: сервер повертає
`tool_calls`, а виконує їх клієнт.

**Stream + auto:** проміжні раунди не стрімляться, щоб клієнт не бачив
службових блоків. Клієнт отримує один фінальний текстовий кадр і `stop`.
Для построкового стріму використовуйте звичайний режим без auto-тулів.

### Субагенти

`subagent` створює окрему сесію DeepSeek із власним системним промтом:

- один виклик: `task` або `tasks[]` (до 4 паралельно);
- глибина вкладеності — до 2 рівнів;
- до 4 раундів інструментів усередині;
- дедлайн — 4 хвилини;
- усі запити проходять через захист акаунта (паузи й ліміти спільні);
- тимчасова сесія видаляється після завершення (якщо `apiDelete`);
- назовні повертається лише фінальний текст.

Приклад:

```json
{"auto_tools":true,"messages":[{"role":"user",
 "content":"Порахуй 17% від 480 і скажи, котра година в Токіо"}]}
```

Модель сама викличе `calc` і `time`; для складнішої задачі — `subagent`.

## Публічний доступ

Застосунок слухає лише `127.0.0.1`. Щоб користуватися API ззовні, підніміть
тунель — він дає HTTPS-адресу й не потребує ні карти, ні відкритих портів:

```bash
cd ~/downloads/funachat/tunnel
./start.sh              # Cloudflare quick tunnel (резерв — zrok)
```

Далі в застосунку: **Налаштування → API → Публічний доступ → «З файлу»**.
Кнопка «Перевірити» робить `GET /health` із ключем, «Копіювати конфіг
клієнта» дає Base URL, ключ і модель.

Через один origin доступні:

| Шлях | Що це |
|---|---|
| `/health`, `/v1/*` | Local API (потрібен `fk-…`) |
| `/updates/latest.json` | маніфест оновлень |
| `/updates/FunaChat.apk` | підписаний APK (Range підтримується) |

Ліміт — 120 запитів/хв на IP; за тунелем IP береться з `CF-Connecting-IP`
або `X-Forwarded-For`, тож квота не спільна для всіх клієнтів.

Публічний API не виконує файлових інструментів, `funa-bridge` і ADB:
доступні лише `time`, `calc`, `convert`, `random`, `base64`, `hash`,
`skill` і `subagent`.

Деталі та налаштування стабільного домену — `tunnel/README.md`.
